# إدارة بوفيه سيوة — V1.2.0

برنامج PWA مستقل لإدارة صاحب البوفيه، وليس برنامج البيع أو الجرد.

## الوظائف المنفذة

- منيو 34 صنف من الصور، منها 5 أصناف أسعارها غير محددة لحين إدخالها.
- تعديل/إضافة/حذف الأصناف والفئات والأسعار، مع الحالات (شغال، تجربة، مؤجل، ملغي).
- خطة مشتريات ثابتة لمدة 7 أيام، مبنية على متوسط استهلاك كل منتج، ورصيد اختياري، وحجم عبوة الشراء وسعرها.
- احتياطي يومين للأصناف التي تتحمل التخزين، ومن دون احتياطي تلقائي للأصناف قصيرة الصلاحية.
- الوصفات والمكونات المشتركة، وتكلفة الطبق إذا اكتملت أسعار جميع المكونات، وخطة الخامات حسب أطباق الأسبوع للوصفات الشغالة فقط.
- الموردون، معدات التشغيل، التجارب والقرارات مع قوائم خطوات قابلة للتأشير.
- إدخال كميات الجرد من نص بعد قراءة ورقة الجرد في ChatGPT، مع مراجعة قبل الحفظ.
- نسخ خطة الأسبوع لإرسالها إلى ChatGPT، وتصدير/استيراد نسخ احتياطية JSON.
- العمل دون إنترنت بعد التثبيت على موقع HTTPS، مع تخزين البيانات على الجهاز.
- تجهيز للمزامنة التلقائية باستخدام Supabase في مشروع مستقل جديد فقط، بعد تهيئة المشروع وتسجيل الدخول.

## التشغيل

يمكن فتح `index.html` من الكمبيوتر للتجربة المحلية. للتركيب كتطبيق PWA والمزامنة، انشر محتويات المجلد على HTTPS (مثل GitHub Pages) وافتح الموقع. لا تحتاج مكتبات خارجية أو حزم npm.

محليًا عبر Python: `python -m http.server 8080` ثم افتح `http://localhost:8080`.

## تفعيل المزامنة مستقبلًا

1. أنشئ مشروع Supabase **مستقل جديد** لو متاح بدون رسوم. لا تمس مشاريع البوفيه أو الجرد الحالية.
2. نفّذ ملف `supabase-setup.sql` في SQL Editor للمشروع الجديد فقط.
3. من Authentication أنشئ حسابك أنت وحدك وعطّل Signups العامة.
4. من إعدادات التطبيق أدخل رابط المشروع و`publishable key` أو `anon key` وبريد المستخدم وكلمة المرور وسجّل الدخول.
5. كل تعديل يُحفظ محليًا أولًا، ثم تُجرّب المزامنة تلقائيًا عند وجود الإنترنت. الأحدث على مستوى السجل هو الذي يغلب عند تعديل نفس السجل من جهازين.

تستخدم المزامنة شرط المراجعة revision لتقليل تعارض تحديثات الأجهزة. لا يوجد ضمان مطلق عند تغيير ساعة الجهاز أو الكتابة المتزامنة على نفس السجل؛ استخدم النسخ الاحتياطية المهمة.

## اعتبارات دقيقة

- الأسعار الفعلية في بيانات البداية هي أسعار البيع التي ظهرت في صور المستخدم. أسعار الشراء غير المعروفة فارغة. سعر اللبن 50 جنيه/لتر والقمح الجاف 40 جنيه/كيلو مدخلان بناء على المستخدم.
- وصفة البليلة في حالة «تحت التجربة»، بكمية 250 مل من القمح المسلوق و150 مل لبن و12 جرام سكر و3 جرام نشا. لا يتم حساب القمح الناشف من 250 مل مسلوق دون قياس معامل السلق عند المستخدم.
- «أم علي» و«رز بلبن» صنفان شغالان، لكن وصفاتهما لم تدخل في خطة الشراء لأن المقادير الدقيقة لم تُعتمد بعد.
- إذا لم يُدخل المستخدم متوسط استهلاك منتج فلا يتم تخمينه. وإذا لم يدخل الرصيد، تُعرض الحاجة بافتراض عدم خصمه مع تنبيه «غير معروف».
- ليس هناك ذكاء اصطناعي داخل البرنامج ولا تكلفة API ولا اتصال تلقائي ببرنامج العسكري أو برنامج الجرد.
- صورة ورقة الجرد لا يتم تحليلها داخل التطبيق: تُقرأ هنا في ChatGPT، ثم تُلصق قائمة النص في نافذة «إدخال الجرد من النص» بالبرنامج.

## خصوصية البيانات

تخزن النسخة المحلية البيانات في متصفحك (`localStorage`) ولذلك مسح بيانات الموقع قد يمسحها. استخدم «نسخة احتياطية» بانتظام. لا تشارك مفتاح `service_role` أو أية مفاتيح سرية داخل الواجهة. استخدم Publishable Key فقط مع RLS.

- سجل عروض الموردين: سعر العبوة والشحن وتكلفة الوحدة، من غير تغيير تلقائي لأسعار الشراء إلا بقرار المستخدم.

- زر فتح ChatGPT من الإعدادات، ونسخ خطة الشراء كنص. لا يوجد ربط مباشر حاليًا.
- تحديث Service Worker لإصدار 1.1 مع حفظ موارد الواجهة أوفلاين.

## وضع النشر والمزامنة
- ملفات GitHub Pages جاهزة للرفع إلى مستودع **جديد منفصل**. رفعها وتفعيل Pages يتم بعد توفير مستودع جديد.
- المزامنة تحتاج مشروع Supabase مستقل وحسابًا واحدًا. لا تستخدم القواعد الحالية الخاصة بالبيع والجرد.
- لا تنشئ مشروعًا مدفوعًا قبل مراجعة التكلفة. Supabase Free يدعم مشروعين نشطين مجانيين إجمالًا عبر منظمات المالك.

## نتائج الاختبار (البيئة المحلية)
اختبار تلقائي للمنيو وتعديل السعر والحفظ، وتخطيط 7 أيام، وتسجيل المشتريات، وقراءة نص الجرد، وتجميع خامات وصفة، وإضافة مورد وعرض سعر، ومحاكاة سحابية لمرحلة المصادقة والدمج.
الاختبارات ناجحة. **لم يُجرَ اختبار حي للمزامنة مع مشروع Supabase جديد، ولم يتم اختبار Service Worker على جهاز iOS حقيقي**.

## النشر عند تجهيز المستودع
1. أنشئ مستودع GitHub جديد، منفصلًا تمامًا عن `buffet-sarab-app` و`El-gard`.
2. ارفع **محتويات** هذا المجلد إلى جذر المستودع الجديد (بما فيها `.nojekyll` و`assets`).
3. Settings → Pages → Deploy from a branch → `main` → `/ (root)`، ثم Save.
4. جرّب فتح الرابط https وتثبيت الموقع من Safari / Chrome.
5. قبل أي مزامنة يجب وجود مشروع سحابي مستقل، وتشغيل `supabase-setup.sql` عليه فقط.


## إضافات V1.2
- شاشة المنيو تعرض السعر الحالي فقط، وسهمًا أحمر مع (+ فرق السعر) عند الزيادة، أو سهمًا أخضر مع (− فرق السعر) عند النقص. لا توجد خانات سعر سابق أو تاريخ تعديل في الواجهة. يُحفظ فرق آخر تغيير للسعر داخل السجل، ولا يتغير عند تعديل الاسم أو الفئة فقط.
- المنتجات والخامات تدعم الكميات بالجرام والملليلتر والقطعة. يمكن تحديد حجم عبوة الشراء بالكيلو أو اللتر؛ البرنامج يحولهما داخليًا إلى جرام وملليلتر، ويعرض الشراء بوحدة العبوة المختارة.
- مثال: شراء 1 كيلو قمح بـ40 ج و100 جرام في وصفة = 4 ج تكلفة قمح. شراء 1 لتر لبن بـ50 ج و150 مل في وصفة = 7.50 ج.
- إذا كانت لديك بيانات قديمة أُدخلت بوحدة كيلو أو لتر، تُحوّل الكميات المرتبطة بها عند تحميلها إلى الوحدات الأساسية دون تكرار التحويل عند الفتح التالي.
- جميع البيانات المحلية تستخدم نفس مفتاح التخزين والنسخ الاحتياطي القديم، فلا تحذف النسخة القديمة قبل أخذ نسخة احتياطية.
- لم يتم نشر البرنامج أو تفعيل Supabase. برنامج العسكري والجرد مستقلان ولم يمسهما أي تغيير.
